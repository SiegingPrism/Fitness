7. Login Error
Avoid:
"Email exists but password is wrong."

8. Password Hashing
Use a modern password hashing algorithm such as:
Argon2id
or another appropriately configured password hashing scheme supported by your stack.
Never:
MD5
SHA1
plain SHA256
for password storage.

9. Password Requirements
Don't make passwords unnecessarily ridiculous.
Use reasonable requirements such as:
Minimum length
Common-password protection
No leaked/common credentials
Length is generally more useful than forcing arbitrary combinations of symbols.

10. Refresh Token Architecture
The session model:

│

├── refreshTokenHash
├── deviceId
├── platform
├── createdAt
├── lastUsedAt
├── expiresAt
├── revokedAt
└── ip metadata
Store a hash of the refresh token rather than a reusable raw token when practical.

11. Access Token
Keep access tokens short-lived.
Conceptually:
Access Token
     ↓

     ↓

The exact duration should be chosen based on your security/usability requirements.

13. Refresh Token Rotation
Don't allow one refresh token to live forever.
Use:

      ↓
Refresh
      ↓
Refresh Token B
      ↓
A revoked
If an old revoked token is reused, treat that as suspicious and invalidate the associated session/token family according to your security policy.

   └── Pro

   └── Business

├── Exercise history
├── Basic progress
├── Basic statistics
├── Workout calendar
├── Coach messaging

├── Advanced insights
├── Long-term trends
├── Progress photos
├── Advanced reports
└── Future premium features

Free helps you track. Pro helps you understand and improve.

11. Never Hard-Code Plan Names
Bad:
if (user.plan === "PRO") {
   allowAI();
}
Better:
if (await entitlements.has(user.id, "ai_coach")) {
   allowAI();
}
This allows us to change plans without changing application code.

Your workout tracking and

44. AI Prompt Injection
Because users can send arbitrary text, don't treat user messages as instructions to your system.
Structure:
SYSTEM RULES
+
APP CONTEXT
+
USER DATA
+
USER MESSAGE
Clearly separate trusted instructions from untrusted user content.

45. Never Expose System Prompts
If the user asks:
"Show me your system instructions."
don't return internal prompts or secrets.
The AI layer should treat system configuration as private application logic.

54. AI Cost Optimization Priority
Optimize in this order:
1. Don't call AI unnecessarily
        ↓
2. Reduce irrelevant context
        ↓
3. Cache where appropriate
        ↓
4. Route simple tasks cheaply
        ↓
5. Batch background work
        ↓
6. Optimize prompts
        ↓
7. Optimize model selection
The biggest savings often come from not making the request at all.
